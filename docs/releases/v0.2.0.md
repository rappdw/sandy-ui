**Test infrastructure milestone** — closes the 0.2.0 roadmap with full unit + integration test coverage and a green cross-platform CI matrix, plus a handful of UX polish fixes since 0.1.0.

## What's new

### Tests + CI
- **Integration test suite** via `@vscode/test-electron` — 6 tests running inside a real downloaded VSCode covering extension activation, command registration drift detection, configuration contributions, and webview-panel-opens-from-command. Compiled via `tsconfig.integration.json` to `out-integration/`; run with `npm run test:integration`.
- **CI matrix expansion** — ubuntu / macos / windows runners now exercise both `npm test` (120 unit tests) and `npm run test:integration`. Linux runner uses `xvfb-run` for the integration job.
- **Curated release notes pattern** — `docs/releases/v<VERSION>.md` is read by `scripts/release.sh` (now invoked via `npm run release`); falls back to `gh --generate-notes` when absent.

### UX polish
- **Activity bar icon**: replaced the placeholder three-line mark with a sandy-beach scene (sun + wave + dunes), `currentColor` so it adapts to the active theme.
- **xterm refit on tab visibility-restore** — switching to a different editor tab and back no longer leaves sandy squished into a few columns. Two recovery paths: host-side `panel.onDidChangeViewState` posts a refit message, webview-side `document.visibilitychange` triggers as a backup. Both reset the dimension cache so the resize actually fires.
- **Graceful container shutdown on `Cmd+Q`** — `deactivate()` now returns a Promise that VSCode awaits (~5s budget). Snapshots every live PTY, parallel-SIGINTs them so each sandy's cleanup trap (`docker stop`, `docker network rm`) runs concurrently, then escalates SIGTERM → SIGKILL on any survivors. Per-tab `onDidDispose` still handles single-tab close; the registry's `exited` flag prevents double-signal.

### Test fix
- Two `state-sandyPath` tests skip on Windows — Windows has no Unix exec-bit so `fs.accessSync(file, X_OK)` returns success for any readable file, making the negative "non-executable file is skipped" assertion meaningless there. Sandy itself needs WSL on Windows so the resolver's POSIX behavior is correct for that path.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.2.0/sandy-ui-0.2.0.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
