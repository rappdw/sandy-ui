**Native text selection + wheel scroll in the sandy terminal** — plain drag-to-select now works with no modifier key, while mouse-wheel scroll inside tmux and clean fullscreen rendering all keep working at the same time.

## What's new

### The mouse split

Previously these three were mutually exclusive, because sandy's inner tmux exposes "mouse on" as a single terminal-level switch that bundles mouse tracking (click/drag) with the wheel. Leaving it on forced you to hold ⌥ Option to select; turning it off killed wheel scroll. 0.4.0 splits that switch in the webview:

- **Drag selects natively, no modifier.** The mouse-tracking enable sequences (DECSET `1000/1001/1002/1003`) are swallowed so xterm never forwards click/drag — selection is always native.
- **Wheel still scrolls tmux.** The wheel alone is re-injected to the PTY as SGR mouse events, so tmux (whose own `mouse on` is untouched) keeps scrolling.
- **Fullscreen stays clean.** Alt-screen (`1049`) and other control sequences pass through untouched, so TUIs like claude and vim render and restore correctly.

### Rough edges smoothed

- **Selection clears on wheel-scroll** — tmux repaints in place, so a stale highlight would otherwise sit over now-different text.
- **Post-mouseup guard** absorbs trackpad inertia, so finishing a selection no longer intermittently scrolls or clears it.

### Trade-off

Clicking *inside* a TUI app no longer reaches it — only the wheel and keyboard do. Selection-over-app-click is the deliberate choice for sandy's workflow.

The proper long-term fix is sandy-side (`handoffs/sandy-tmux-mouse-and-passthrough.md`); until that lands, this webview-side split delivers the behavior now.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.4.0/sandy-ui-0.4.0.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
