**Sessions survive VSCode restarts.** With sandy ≥ 1.1.0's daemon mode, closing the Sandy tab (or quitting VSCode entirely) now *detaches* instead of stopping — the session keeps running on the host, and Stop is the explicit teardown action.

## What's new

### Daemon-mode session persistence — the behavior change

- **Closing the Sandy tab no longer stops sandy.** With `sandy.persistSessions` on (the new default), launch runs sandy in daemon mode: tab close / VSCode quit detaches, the host-side session persists (sandy's `--restart unless-stopped` container policy even survives a reboot), and relaunching the same workspace re-attaches instead of spawning a duplicate. Explicit **Stop** (tree context menu or status bar) is now the only thing that tears a session down — if you relied on "close the tab to stop sandy," check the Stop command instead.
- **Launch is two-phase and visible.** `sandy --start` runs first, in the same terminal tab, so you watch image build / seeding happen live instead of staring at a blank pane; once it exits 0 the tab swaps to `sandy --attach` (`sandy-ui#12`'s frozen daemon contract). `--start` is idempotent — relaunching an already-running workspace no-ops through it straight to attach.
- **Requires sandy ≥ 1.1.0**, feature-detected via schema capabilities (`--print-schema`'s `capabilities.daemonMode`). Older sandy, or `sandy.persistSessions` set to `false`, falls back unchanged to the pre-0.6.0 lifecycle: closing the tab stops sandy via signal escalation, same as always.

### Tree & status bar: persisted sessions are visible

- Sandbox tree items for daemon sessions show a `persisted` marker in the description (plus attached-client count when sandy reports it) and a `Daemon:` / `Clients:` line in the tooltip.
- The status bar's session count now includes persisted daemon sessions that have no local client in this VSCode window — it no longer disappears just because you closed every tab; the quick-pick (click the status bar item) lists them alongside local sessions, and picking one attaches.
- A new top-level tree node — "⚠ N orphaned sandy networks" — appears when sandy reports leaked `sandy_*` Docker networks from crashed/killed sessions (`rappdw/sandy#20`). Click it to prune.

### New command

- **Sandy: Prune Orphaned Networks** (also reachable by clicking the tree's orphan-networks node) runs `sandy --prune-orphans` and refreshes state on success.

### Cleanup

- Removed the `workspace_path` enrichment bridge (`state/enrich.ts`) that recovered a missing `workspace_path` by reading each sandbox's `WORKSPACE.json` directly. Sandy ≥ 1.0 emits `workspace_path` natively in `--print-state`, and 0.6.0's daemon features already put the floor at sandy 1.1.0, so the bridge had nothing left to bridge. Fixes #13.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.6.0/sandy-ui-0.6.0.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
