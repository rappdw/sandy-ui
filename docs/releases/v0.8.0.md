**Stranger-proofing** — the release that makes sandy-ui installable by someone who didn't build it. A first-run walkthrough, a real compatibility gate, opt-in session auto-restore, and groundwork for running the whole thing against a remote sandy over Remote-SSH. (See ROADMAP_1.0.md.)

## What's new

### First-run: "Sandy: Get Started" walkthrough (#31)

A VS Code Walkthrough, surfaced on install and via **Sandy: Get Started**, that replaces "figure it out from error strings":

- **Live fix-it steps** — sandy-installed and Docker-reachable checks tick green the moment you fix them (driven by real context keys from the same checks the extension already runs), no reload.
- First-launch step, then the **persistence gotcha up front** (closing a tab detaches, it doesn't stop — Stop is explicit), then a settings + approval-model tour.

### Compatibility gate (#30)

- Declares **sandy ≥ 1.0.0, config schema v1** as a single source of truth (`src/schema/compat.ts`).
- On activation: too-old sandy → actionable error; schema newer than supported → soft warning + best-effort render; a major schema jump → refuse-with-upgrade-pointer. **Non-blocking by design** — it informs, never disables the extension (sandy still enforces its own compatibility at launch).
- **The mock-schema fallback is now loud**: if sandy is installed but `--print-schema` fails, the settings panel banners it and a one-time warning fires — no more silently editing against stale field definitions that look real.

### Opt-in session auto-restore (#32)

- `sandy.restoreSessionsOnStartup` (default **off**): on opening a workspace that has a persisted daemon session running on the host, reopen the Sandy tab attached to it — the true "quit VSCode, reopen, everything's back". Respects `persistSessions`, never surprises a fresh profile (gated on having launched at least once), and defers cleanly to a pending cross-window launch.

### Remote-SSH groundwork (#37)

- Pinned `extensionKind: workspace` so under Remote-SSH the extension host runs on the **remote**, driving *that* machine's sandy — the full UX pointed at an always-on server (e.g. a DGX) with the session staying put there. Investigation confirmed the binary resolution, reveal, and clipboard paths are already host-agnostic. The from-source-on-remote install path works today; the packaged path is folded into #33 (node-pty needs the remote's server-Node ABI). New README section covers it.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.8.0/sandy-ui-0.8.0.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
