**Hardening release** — a complete source review (28 findings, 23 fixed) plus the CPU-sawtooth polling fix. Four of the findings were high-severity, including one where disabling `SANDY_SKIP_PERMISSIONS` from the settings UI didn't actually disable it.

## What's new

### Settings save correctness (the reason this is 0.5.0, not 0.4.2)

- **Bools now save as `true`/`false`.** The old `1`/`0` encoding matched *neither* branch of sandy's checks (bash tests `= "true"`, node paths test `!== 'false'`) — so unchecking `SANDY_SKIP_PERMISSIONS` left the permission bypass **active**, and checking a bool silently disabled the feature. Existing files with `1`/`0` still render correctly in the form; re-save to normalize them.
- **Clearing a field now actually clears it.** Empty values previously vanished from the save payload and the merge resurrected the old value — there was no way to unset a key (or uncheck every agent) from the UI. Empty now deletes the key; blank secrets still mean "keep current".
- **Secrets no longer leak into logs or webview state.** The save read-back printed plaintext values (including API keys) to the output channel — now key names + status only. Typed-but-unsaved secrets are no longer persisted via webview state either.

### Session lifecycle fixes

- **Re-attach no longer kills the session it's re-attaching.** Picking a detached session for a different workspace used to reload the window — taking the extension host and the PTY down with it. Now attaches in place; no reload, ever, when a live session exists.
- **No more duplicate Sandy tabs.** Launching a workspace that's already attached reveals the existing tab instead of opening a second panel that silently stole the stream.
- **Stop is exit-aware** — closing a tab completes as soon as sandy exits instead of always sitting through the 3s+2s escalation timers.
- The OSC-notification `●` tab badge now clears when you refocus the tab.
- **Typing works immediately — no more extra click.** On launch and on Cmd+Tab-back, VSCode focused the webview iframe but not xterm's input textarea inside it; the bridge now forwards iframe focus to the terminal.

### CPU: polling is gated, not fixed-interval

Each `sandy --print-state` spawns ~9 docker CLI processes; polling every 5s in every VSCode window produced a visible sawtooth in Activity Monitor. Polling now runs at 5s only while the Sandy tree is visible in a focused window, 60s unfocused, and **stops entirely when the view is hidden** — background windows do zero docker spawns. The poller also passes `light` so the sandy-side fix (rappdw/sandy#18: 9 spawns → 1) activates automatically when it ships.

### Reliability & safety

- **Stale-lock sweep matches sandy's exact lock format** — the loose prefix match let workspace `foo` claim `foo-2`'s locks, and the orphan-recovery flow could offer to SIGTERM the *other* project's live sandy.
- **PIDs owned by another user now count as alive** (EPERM ≠ dead) — a live lock can't be swept by mistake.
- The approval modal — the security gate — migrated from vanilla JS into the typechecked TS/esbuild pipeline (rendering behavior unchanged: verbatim `textContent`).
- Settings panel no longer blocks the extension host while sandy answers `--version`/`--print-schema` (up to ~15s when docker wedged) — schema fetch is fully async.
- Terminal mouse split edge cases: mixed DECSET sequences can no longer silently re-enable tracking (breaking drag-select), and horizontal trackpad motion no longer disturbs vertical scroll accumulation.

The full findings catalog — including what was deliberately *not* changed and why — is in [`docs/reviews/2026-07-03-code-review.md`](https://github.com/rappdw/sandy-ui/blob/main/docs/reviews/2026-07-03-code-review.md).

### Project operations

- Sandy-side asks migrated from `handoffs/` docs to GitHub issues with full specs embedded: [#16 teleport](https://github.com/rappdw/sandy/issues/16), [#17 daemon-mode](https://github.com/rappdw/sandy/issues/17), [#18 print-state light](https://github.com/rappdw/sandy/issues/18), [#19 workspace_path](https://github.com/rappdw/sandy/issues/19), [#20 network cleanup](https://github.com/rappdw/sandy/issues/20).
- `sandy teleport` designed (checkpoint a workspace + agent context to a remote server, resume in tmux) — spec in #16, dotfiles prototype handoff in-repo.
- macOS TCC downgraded from "distribution blocker" to "minor UX note" in the spec after dogfooding showed the prompt cascade only occurs with a `$HOME`-wide workspace, which the extension already prevents. **The remaining distribution gate is node-pty packaging.**

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.5.0/sandy-ui-0.5.0.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
