**Wheel-scroll tuning + a live scroll-speed setting** — a follow-up to 0.4.0's wheel-scroll-to-tmux feature that makes scrolling feel right on both trackpads and mouse wheels, and lets you tune it without a reload.

## What's new

### Device-aware scroll

One divisor can't serve both input devices: trackpads fire a stream of small deltas (which want accumulation for fine control), while mouse wheels fire a few big notches (which want an immediate, snappy jump). The wheel handler now branches on delta size — small pixel deltas bank in an accumulator and emit a line once they cross the threshold; large deltas (and line/page-mode events) emit immediately.

### `sandy.terminal.scrollSensitivity` setting

A single user-facing knob, mirroring VSCode's own `terminal.integrated.mouseWheelScrollSensitivity`:

- Number, default `2`, range `0.1`–`10`. Higher scrolls faster, lower gives finer control.
- Scales both device paths uniformly — the four internal tuning constants stay as implementation details.
- **Applies live.** Pushed host→webview over the existing message channel on launch and re-pushed on configuration change, so changing it updates the running terminal with no reload.

Find it under **Settings → search "sandy scroll"**, or set `"sandy.terminal.scrollSensitivity"` in your settings JSON.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.4.1/sandy-ui-0.4.1.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
