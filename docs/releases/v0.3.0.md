**Multi-session + supervisor maturity** — closes the 0.3.0 roadmap with a real session lifecycle owner, detach/re-attach, status bar quick-pick, and a safety net for the "I came back to a workspace where sandy is still running externally" case.

## What's new

### Session management

- **`PtySupervisor`** owns every sandy session, keyed by workspace path. Replaces the per-panel PTY tracking that lived in closures inside `webviewPanel.ts`. State machine: spawn → attach → (detach → re-attach, or stop). One sandy per workspace at a time.
- **Detach (this VSCode session)** right-click action — closes the webview tab but keeps the PTY alive. Re-attach by clicking the same sandbox in the tree, or by clicking the new status bar item. The naming is honest: detach is bounded to this VSCode session; quitting VSCode takes detached sessions down with it. True cross-restart persistence is the [`sandy-daemon-mode.md`](handoffs/sandy-daemon-mode.md) handoff territory.
- **Stop sandy** explicit context-menu action with signal escalation (`SIGINT → 3s → SIGTERM → 2s → SIGKILL`).
- **Status bar item** — `$(server-process) N sandy` whenever the supervisor has live sessions, hides otherwise. Detached sessions show as `($(eye-closed) M detached)` in the same item. Click → quick-pick listing every session by workspace path; selecting an attached session reveals its panel, selecting a detached session re-attaches.

### Tree improvements

- **Tree badge knows about supervisor sessions**. Sandboxes you spawn via sandy-ui show **▶ running** immediately — no waiting on the 5s `--print-state` poll, and no longer hostage to sandy `--print-state` mis-classifying live containers as locked. The supervisor's view outranks sandy's report when we know we have a live PTY for the workspace.
- **Detach + Stop menu items** appear on both `running` and `locked` sandboxes (covers the case where sandy reports the container as locked even though it's running).

### Re-attach paint correctness

- **tmux repaint via SIGWINCH on re-attach** — fresh xterm.js had no scrollback, and tmux only emits diffs from what it thinks the terminal is showing, so re-attached terminals appeared blank. Now the supervisor triggers a resize-toggle (`rows → rows-1 → rows`) right after attach; tmux always responds to SIGWINCH with a full repaint. ~140ms of imperceptible jitter, then the screen is properly populated.

### Stuck-state recovery

- **Orphan-from-prior-VSCode-session detection on launch**. When the lock sweep finds a live-PID lock for the workspace but the supervisor has no session for it (typical post-VSCode-quit state where sandy's cleanup trap got cut short), a modal asks: "Stop existing & launch fresh / Cancel". Force-stop SIGTERMs the orphan PID (gives sandy's trap 3s to run docker stop / network rm), force-removes any surviving lock files, then proceeds with the normal spawn. Dramatically improves the "I came back, sandy is stuck" experience.

### Sandy-side handoffs queued (not yet shipped)

Two new handoffs in `/handoffs/` ready to paste into a sandy-repo agent when you're ready to do sandy-side work:

- **`sandy-daemon-mode.md`** — adds `sandy --start` / `--attach` / `--stop` so session lifetime decouples from any single client. Once landed, sandy-ui's detach can survive VSCode restarts, and cross-client access (terminal + VSCode) becomes natural. The single biggest UX win available.
- **`sandy-docker-network-cleanup.md`** — robust cleanup-trap behavior + prune-on-startup so the recurring "all predefined address pools have been fully subnetted" error class disappears.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.3.0/sandy-ui-0.3.0.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
