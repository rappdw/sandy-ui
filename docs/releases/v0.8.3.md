**Catching up with sandy 2.x** — a hotfix for two bugs that hit every sandy-ui user on current sandy.

sandy moved from 1.8 to 2.7 in about three weeks, and its introspection `schema_version` from 1 to 4. sandy-ui renders all of that correctly; two things around it didn't.

## Fixed

### An error popup on every window

sandy-ui's compatibility check accepted only schema 1. On sandy 2.6 and later it showed an **error on every window activation** telling you to "update the sandy-ui extension before continuing" — when no newer sandy-ui existed.

The check now:

- accepts **schema 4** (sandy 2.6.0 and later) silently, and schemas 2 and 3 (sandy 2.0–2.5) with a mild warning. The 2→3→4 changes removed only fields sandy-ui never reads;
- treats a schema newer than it knows, within sandy 2.x, as a **warning** that says sandy-ui keeps working — sandy's deprecation policy means a field sandy-ui reads can't vanish within a major without sandy-ui being told first;
- reserves an **error** for sandy 1.x, and for a new sandy major (3.0+), which may change what a field means without notice;
- shows each of these **once per sandy version**, never on every window.

No message tells you to do anything "before continuing" any more.

### The settings panel hid three-quarters of your settings

sandy 2.x added a new setting type, `path` (`SANDY_SCREENSHOT_DIR` is one). sandy-ui's settings form had no fallback for an unrecognized type, so the first `path` setting threw an error and **every setting after it silently disappeared** — 46 of 62 on sandy 2.7.1, with nothing visible to say anything was wrong.

The form now renders `path` settings as text fields, renders any type it doesn't recognize as a plain text field instead of failing, and renders each setting independently, so one problem field can never take the rest down with it.

### Settings is read-only for now

Showing every setting again exposed older problems in how the panel **saves**, and they predate this release:

- Save wrote every setting on the form, including ones you never touched. With the full sandy 2.x list on screen, one Save would have written a retired setting that sandy 2.6+ refuses outright, so every later launch would fail.
- Ten settings that aren't secrets — among them `SANDY_ALLOW_NO_ISOLATION`, `SANDY_SKIP_PERMISSIONS` and `SANDY_ALLOW_HOSTS` — were saved to your **secrets** file, where the panel could neither show nor clear them. **0.8.2 does this on any Save.** Turning isolation off and saving could leave the panel showing it on.

Rather than ship a rushed fix to the code that writes your config, **saving from the Settings panel is turned off** in this version. The panel shows every setting and says which file to edit. Editing from the panel returns once the fix is complete and tested ([#53](https://github.com/rappdw/sandy-ui/issues/53)).

**Check whether 0.8.2 left anything behind.** If you ever saved from the Settings panel, look in `~/.sandy/.secrets` and `<workspace>/.sandy/.secrets` for any of `SANDY_SSH`, `SANDY_SSH_KEYS`, `SANDY_SKIP_PERMISSIONS`, `SANDY_ALLOW_NO_ISOLATION`, `SANDY_ALLOW_LAN_HOSTS`, `SANDY_LOCAL_LLM_HOST`, `SANDY_ALLOW_HOSTS`, `SANDY_EXTRA_ENV`, `SANDY_AGENT_ARGS` or `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`. sandy-ui put them there, not you, and they're safe to delete. Run this from the folder that holds your projects:

```bash
grep -nE '^(SANDY_SSH|SANDY_SSH_KEYS|SANDY_SKIP_PERMISSIONS|SANDY_ALLOW_NO_ISOLATION|SANDY_ALLOW_LAN_HOSTS|SANDY_LOCAL_LLM_HOST|SANDY_ALLOW_HOSTS|SANDY_EXTRA_ENV|SANDY_AGENT_ARGS|CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS)=' ~/.sandy/.secrets */.sandy/.secrets 2>/dev/null
```

## Requirements

**sandy 2.6.0 or later is now the supported floor** (introspection schema 4). sandy 2.0–2.5 work on a best-effort basis. sandy 1.x is no longer supported — sandy 2.x itself refuses 1.x-created sandboxes, so if you're upgrading sandy as well, see sandy's 2.0 notes on `sandy --reset-sandbox`.

## Under the hood

- Real `sandy --print-schema` output from v2.7.1 is checked in as a test fixture, and the parser and compatibility check are tested against it.
- Groundwork for re-enabling Save is in place but switched off: the panel will send only changed settings, measured against what your file actually holds, and the host now leaves a config file byte-for-byte untouched when nothing in it changes.
- Setting types are defined in one place, with a test that fails if the host and the settings panel disagree, and a compile-time check that the panel handles every type it declares.
- Unit suite 289 → 312.

## Install

```bash
curl -L https://github.com/rappdw/sandy-ui/releases/download/v0.8.3/sandy-ui-0.8.3.vsix -o /tmp/sandy.vsix
code --install-extension /tmp/sandy.vsix
```

Then Cmd+Shift+P → "Developer: Reload Window".
